LLBot 手机版 Ubuntu 手动部署入口
版本：LLBot v8.3.2 ARM64。本说明对应授权阶段，只开放本机 WebUI，不开放 OneBot，也不设常驻自启。

准备情况
仓库已有 tool/llbot_local.py 和 tool/llbot_local_guard.mjs。运行副本是手机上已准备并验证的
~/.local/share/oc-plus/qq-onebot-poc/llbot/v8.3.2/runtime-local-v1/ 。
脚本按整个运行副本的文件摘要校验，不下载、不更新、不改系统 Node 或原 NapCat；需要 Linux ARM64 和 Python 3.11+。

以下命令在 /root/projects/opencode-plus 运行。

先检查和离线自检（不用账号）：
python3 -B tool/llbot_local.py check
python3 -B tool/llbot_local.py smoke

开始授权阶段时，在你自己的交互终端首次设置 WebUI 密码：
python3 -B tool/llbot_local.py init-webui

输入不回显，不覆盖已有密码。LLBot 在私有状态目录保留 WebUI 密码文件；不用于 QQ 登录，也不是 OneBot Token。
不要把 WebUI 密码、LLBot Auth Token、QQ 二维码或 OneBot Token 发给聊天。

准备好之后前台启动：
python3 -B tool/llbot_local.py run

等终端提示 WebUI 就绪，再在 OpenCode Plus 打开「设置 → 消息渠道 → QQ 普通账号 → 本机 LLBot 管理页」。
管理页通过现有的内置网页预览打开 127.0.0.1:3080，不跳系统浏览器，也不会替你启动 LLBot。若没启动，页面会提示启动后重试。
本机管理页不打开外链；已有 LLBot Auth Token 时只在内置管理页中填写。
这时只验证管理界面和由本人进行的 LLBot 授权及测试 QQ 扫码。run 可访问授权服务及 QQ，若状态目录已有会话，可能尝试恢复；本轮尚未执行。安装目录与 deployment/ 状态目录分开，启动器不输出进程原始日志。PRoot 及 Node 的权限选项不是原生组件的完整安全沙箱。

另一终端查看状态、停止，或在原终端按 Ctrl+C：
python3 -B tool/llbot_local.py status
python3 -B tool/llbot_local.py stop

仅允许 127.0.0.1:3080，若占用就报错，不换端口，不开放公网。状态写「WebUI 已就绪」不代表 QQ 在线。
本机授权和登录实测通过后，再另行启用 127.0.0.1:13001 的带 Token 正向 WebSocket，验收 OneBot 调用、私聊/群聊、App 最终答复回传和重连。不要预先启用 OneBot 或替换旧端点。
