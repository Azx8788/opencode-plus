LLBot 手机版内置 Ubuntu 一键部署

运行环境
LLBot v8.3.2 官方 Linux ARM64 ZIP，自带 Node。按需下载约 89 MB，安装后运行环境约 172 MB；下载包与运行数据还需要额外空间。
协议端不预装在 APK 中。先在 App 设置中完成内置 Ubuntu 安装；不支持的设备会显示原因。

部署入口
设置 → 消息渠道 → QQ 普通账号 → 本机 LLBot 一键部署 → 一键部署并启动。
App 实际执行下载、校验、安装、配置和启动；页面展示阶段进度、失败与重试，并提供刷新状态、停止和启动。
仅打开页面只检查状态，不安装、不启动。离开页面不会取消共享控制器中的操作，App 环境运行期间会继续。
「本机 → Linux 环境管理」也提供同一管理页入口；此独立入口管理服务，连接导入在 QQ 表单入口完成。

授权与 QQ 登录（必须由本人完成）
1. 等待「本机管理页已就绪」。页面可以查看或复制自动生成的高强度随机 WebUI 密码。
2. 点「打开 WebUI · QQ 登录」，在内嵌的 http://127.0.0.1:3080/ 中使用该密码登录。
3. 本人从 https://auth.luckylillia.com 获取上游 LLBot Auth Token，并在本机 WebUI 中填写。
4. 在 WebUI 继续 QQ 二维码登录。App 不会代办上游授权或扫码。
上游 LLBot Auth Token、本机 WebUI 密码、OneBot Access Token 是三种不同凭据；App 只自动生成后两种。
部署页提供授权网址的复制入口。内嵌本机管理页严格限制同一 HTTP origin，不打开外部链接。
不要把密码、任何 Token 或 QQ 二维码发送到聊天中。

使用本机连接
QQ 登录后才会启动带 Token 的 OneBot 正向 WebSocket：ws://127.0.0.1:3001/，路径为根路径 /，不是 /ws。
从 QQ 表单进入部署页后，显式点「使用本机连接」，才会把本机地址和 Token 填回表单。
此时只是未保存的草稿；保留已有允许用户/群列表，草稿中的渠道开关保持关闭。检查预期 QQ 账号，按需调整允许列表，测试连接，再自行启用并保存。
打开页面、部署或打开 WebUI 都不会替换原有远程端点及凭据，也不会自动启用消息转发。只有正常保存才写入 QQ 渠道配置。
手动或远程 LLBot、NapCat、SnowLuma 仍可在 QQ 表单中设置；原有正向和反向选项保留。

运行与验收
本机 WebUI 只监听 127.0.0.1:3080，OneBot 只监听 127.0.0.1:3001；不会自动换成公网地址。
「管理页已就绪」不代表 QQ 在线，也不代表 OneBot 已开始监听或消息回传通过验收。
如果 WebUI 无法连接，回到部署页刷新状态，必要时启动或重试；停止按钮停止托管服务。
Android 可能终止后台进程，本功能不保证常驻在线。PRoot 不是原生组件的完整安全沙箱。
真实上游授权、QQ 登录、OneBot 调用、私聊/群聊、App 最终答复回传和重连仍需本人在设备上验收。UI 自动测试使用假部署控制器，不执行真实部署或账号登录。
